# 功能：用户刷题

## 1. 功能目标

用户可以在安卓 APP 中进行 Java 面试单选题练习。系统支持顺序刷题、随机刷题、按标签刷题、搜索后刷题，并在用户答题后展示结果和解析。

## 2. 用户故事

作为准备 Java 面试的用户，我希望打开 APP 后可以快速开始刷题，答完后立即知道对错和原因。

## 3. 功能范围

### P0

- 获取题目详情。
- 获取下一题。
- 提交答案。
- 展示正确答案。
- 展示解析。
- 记录答题历史。
- 错题自动进入错题本。

### P1

- 顺序刷题。
- 随机刷题。
- 按标签刷题。
- 搜索后刷题。
- 跳过本题。
- 在 Android App 中将题目设为“不再出现”，并可恢复。
- 答题耗时记录。

### P2

- 模拟面试模式。
- 每日练习。
- 学习计划。
- 根据薄弱标签推荐题目。

## 4. 刷题模式

### 顺序刷题

按题目 ID 或创建时间顺序获取下一题。

适合：

- 系统性刷完整题库。

### 随机刷题

后端随机返回题目。

适合：

- 日常练习。
- 快速检验知识面。

### 标签刷题

只返回指定标签下的题目。

适合：

- 专项复习，例如 JVM、并发、Spring。

### 错题刷题

从错题本中返回未掌握题目。

适合：

- 复盘薄弱点。

### 收藏刷题

从收藏题目中刷题。

适合：

- 复习重点题。

### 个人屏蔽规则

- Android App 刷题页可将当前题目设为“不再出现”。
- 屏蔽记录按用户保存，不删除题目，不影响其他用户。
- 随机、顺序、标签、搜索、错题和收藏刷题都会排除当前用户已屏蔽的题目。
- App 内的“不再出现”页可查看记录并恢复题目。
- 该功能与管理员全局下线题目相互独立。

## 5. 刷题页状态

### 加载中

展示题目加载状态。

### 未答题

展示：

- 题干。
- 难度。
- 标签。
- A/B/C/D 选项。
- 收藏按钮。
- 提交按钮。

规则：

- 未选择选项时提交按钮不可用，或点击后提示“请选择一个答案”。
- 未提交前不展示正确答案。

### 已答题

展示：

- 用户选择。
- 正确答案。
- 是否正确。
- 答案解析。
- 下一题按钮。

规则：

- 正确选项高亮。
- 用户选错时，用户选项标记错误。
- 答题后本题选项不能再次修改。

### 无题目

展示：

- 当前条件下暂无题目。
- 返回首页或切换模式入口。

## 6. 提交答案流程

1. 用户进入刷题页。
2. 系统加载题目。
3. 用户选择一个选项。
4. 用户点击提交。
5. 前端调用提交答案接口。
6. 后端判断是否正确。
7. 后端记录答题记录。
8. 如果答错，后端更新错题本。
9. 前端展示正确答案和解析。
10. 用户点击下一题。

## 7. 接口

### 获取下一题

`GET /api/practice/next?mode=RANDOM&tagId=1&excludeAnswered=false`

响应：

```json
{
  "id": 1,
  "type": "SINGLE_CHOICE",
  "stem": "关于 Java 中 volatile 的说法，哪一项是正确的？",
  "difficulty": "MEDIUM",
  "options": [
    {
      "id": 11,
      "optionKey": "A",
      "content": "volatile 可以保证 i++ 的原子性"
    }
  ],
  "tags": [
    {
      "id": 10,
      "name": "Java并发"
    }
  ],
  "favorite": false
}
```

### 获取当前练习条件下的题目数

`GET /api/practice/count?mode=RANDOM&tagId=1&excludeAnswered=true`

响应：

```json
{
  "total": 12
}
```

### 提交答案

`POST /api/questions/{questionId}/answer`

请求：

```json
{
  "selectedOptionKey": "B",
  "mode": "RANDOM",
  "timeSpentSeconds": 18
}
```

响应：

```json
{
  "questionId": 1,
  "selectedOptionKey": "B",
  "correct": true,
  "correctOptionKey": "B",
  "answerAnalysis": "volatile 能保证变量可见性，并提供相关内存语义，但不能保证复合操作的原子性。",
  "wrongBookUpdated": false,
  "recordId": 9001
}
```

### 查看题目解析

`GET /api/questions/{questionId}/analysis`

### 设为不再出现

`POST /api/excluded-questions/{questionId}`

### 查看已屏蔽题目

`GET /api/excluded-questions?page=1&pageSize=20`

### 恢复题目

`DELETE /api/excluded-questions/{questionId}`

## 8. 答题记录规则

每次提交都记录一条答题记录。

记录内容：

- 用户 ID。
- 题目 ID。
- 选择的选项。
- 是否正确。
- 刷题模式。
- 答题耗时。
- 答题时间。

重复提交处理：

- 一期可以允许重复提交并记录多次。
- 前端要防止短时间重复点击。
- 后续可以加入 requestId 防重复提交。

## 9. 错题更新规则

答错时：

- 如果错题本没有该题，创建错题记录。
- 如果已经存在，`wrongCount + 1`。
- 更新最近答错时间。
- 标记为未掌握。

答对时：

- 如果错题本存在该题，`correctAfterWrongCount + 1`。
- 是否自动标记掌握由错题本功能规则决定。

## 10. 异常规则

- 题目不存在：提示“题目不存在或已下线”。
- 未选择答案：提示“请选择一个答案”。
- 选项不存在：提示“选项无效”。
- 网络失败：提示“网络异常，请重试”。
- 提交超时：允许用户重试。

## 11. 验收标准

- 用户可以获取题目。
- 未答题前不展示正确答案。
- 用户可以提交 A/B/C/D 中一个选项。
- 提交后展示对错和解析。
- 答错后错题本新增或更新。
- 答题记录成功保存。
- 可以连续点击下一题刷题。
- 用户屏蔽的题目不再进入其各类刷题候选集。
- 用户可以在 Android App 中恢复已屏蔽题目。
