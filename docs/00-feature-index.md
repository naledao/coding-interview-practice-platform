# 功能文档目录

## 1. 产品一句话

这是一个面向 Java 程序员的面试刷题安卓 APP。管理员上传 Markdown 知识文档后，系统调用本地 Codex CLI 自动解析、联网补充资料、生成单选题、自我 review，并通过 MCP 写入 MySQL；用户在安卓 WebView APP 中完成刷题、错题复习、收藏和统计。

## 2. 用户角色

### 普通用户

主要使用刷题相关功能：

- 登录 APP。
- 按标签、分类、随机、顺序刷题。
- 提交答案。
- 查看解析。
- 自动沉淀错题。
- 收藏题目。
- 查看学习统计。

### 管理员

主要使用题库生产相关功能：

- 登录管理端。
- 上传 Markdown 知识文档。
- 查看 Codex 生成任务状态。
- 查看生成日志和产题数量。
- 重新执行失败任务。
- 下线明显不可用题目。

### Codex

系统内的 AI 产题代理：

- 通过 MCP 读取上传文档。
- 提取知识点。
- 联网搜索相关资料。
- 生成单选题。
- 自我 review。
- 打标签。
- 通过 MCP 写入题库。

## 4. 一期功能边界

一期只做：

- 单选题。
- Markdown 文档上传。
- Codex 自动产题。
- Codex 自我 review 后直接入库。
- 用户刷题。
- 错题本。
- 收藏。
- 基础统计。
- Android WebView APP。

一期不做：

- 人工审核。
- 多选题。
- 判断题。
- 简答题。
- 编程题在线判题。
- 社区评论。
- 会员付费。
- 复杂推荐算法。

## 5. 全局业务规则

- 题目必须是单选题。
- 每道题必须有且只有一个正确答案。
- 每道题必须有解析。
- 每道题必须有至少一个标签。
- Codex 生成题目前必须联网补充或校验资料。
- Codex 写库前必须自我 review。
- 管理员不审核题目。
- 系统保留下线题目的能力，用于处理明显错误或不适合展示的题。

## 6. 全局状态约定

### 文档状态

- `UPLOADED`：已上传。
- `PROCESSING`：处理中。
- `PROCESSED`：处理完成。
- `FAILED`：处理失败。

### Codex 任务状态

- `PENDING`：等待执行。
- `RUNNING`：执行中。
- `SUCCEEDED`：执行成功。
- `FAILED`：执行失败。
- `CANCELLED`：已取消。

### 题目状态

- `ACTIVE`：可刷题。
- `DISABLED`：已下线。

### 题目难度

- `EASY`：简单。
- `MEDIUM`：中等。
- `HARD`：困难。

## 8. 全局接口风格

接口统一返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

分页统一返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "items": [],
    "page": 1,
    "pageSize": 20,
    "total": 100
  }
}
```

## 9. 优先级定义

- `P0`：一期必须完成，不完成无法形成闭环。
- `P1`：一期建议完成，影响体验但不阻塞主流程。
- `P2`：后续增强。
